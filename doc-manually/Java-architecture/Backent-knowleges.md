1. 目的论：计算机为何存在
   1.1. 机械化执行一切可描述的过程（图灵机，1936）
   1.1.1. 可计算性与丘奇-图灵论题
   1.1.2. 理想模型三要素：无限纸带（存储）、读写头（I/O）、状态转移表（计算）
   1.2. 通用性：程序即数据（通用图灵机——软件的出生证）
   1.3. 工程化：冯·诺依曼架构（1945）——CPU/Memory/IO 三大资源由此确立
2. 本体论：系统做的唯一一件事——操作状态
   2.1. 变换状态 = 计算（CPU）
   2.2. 跨时间搬运状态 = 存储（Memory/Disk）
   2.3. 跨空间搬运状态 = 通信（Network）
   2.4. 推论：存储与通信同构（WAL 是写给未来的消息；Kafka 既是队列又是日志；纠错码同时用于内存与网络）
   2.5. 核心概念预置：一致性 = 同一逻辑状态的多份时空拷贝之间的吻合问题
3. 第一条根：物理约束——机器的极限
   3.1. 四大约束事实（一切性能/可用技术的总源头）
   3.1.1. 速度鸿沟：CPU ≫ 内存 ≫ 磁盘 ≫ 网络（逐级差 2~5 个数量级）
   3.1.2. 资源有限：单核算力（功耗墙，2005）、内存容量、连接数、带宽
   3.1.3. 不可靠：网络分区、消息丢失乱序、机器宕机
   3.1.4. 延迟不可消除：光速上限、跨地域 RTT 是物理事实
   3.2. 应对策略 A：对抗速度鸿沟 →【性能技术】
   3.2.1. 计算效率（榨干 CPU）
   3.2.1.1. 并行化
   3.2.1.1.1. 进程/线程/协程模型、上下文切换成本
   3.2.1.1.2. 线程池：核心参数、执行流程、拒绝策略、参数调优
   3.2.1.1.3. ForkJoin 与工作窃取
   3.2.1.1.4. 虚拟线程（Java 21）：推翻"线程太贵"的前提
   3.2.1.2. 异步化（不让 CPU 等 I/O）：Future/CompletableFuture、回调、响应式
   3.2.1.3. 就地优化：JIT 编译、逃逸分析、栈上分配、内联
   3.2.1.4. 算法与数据结构（计算的数学下限）
   3.2.1.4.1. 哈希表与扰动函数
   3.2.1.4.2. 红黑树、跳表
   3.2.1.4.3. B+ 树 vs LSM-Tree（读优 vs 写优的根本取舍）
   3.2.1.4.4. 布隆过滤器、位图、时间轮
   3.2.2. 存储效率（对抗"快的小、大的慢"）
   3.2.2.1. 缓存（用快的掩盖慢的）
   3.2.2.1.1. 层级全景：CPU 三级缓存 → JVM 堆 → Redis → Page Cache → CDN
   3.2.2.1.2. Redis 专题：单线程模型、底层数据结构、持久化（RDB/AOF）
   3.2.2.1.3. 缓存三大事故：穿透/击穿/雪崩及其方案
   3.2.2.1.4. 淘汰策略：LRU/LFU/过期机制（空间有限的必然）
   3.2.2.2. 局部性原理：预读、批量、池化（连接池/对象池——"复用"母题）
   3.2.2.3. 顺序化（随机 I/O 变顺序 I/O）：WAL 思想、redo log、AOF、Kafka 日志、LSM
   3.2.2.4. 索引（空间换时间）：MySQL B+ 树、聚簇/二级索引、回表、覆盖索引、索引失效
   3.2.2.5. JVM 的存储版图：运行时数据区（堆/栈/方法区·元空间/程序计数器）、对象内存布局
   3.2.2.6. 回收（有限空间必须循环利用）
   3.2.2.6.1. GC：存活判定、分代假说、三色标记
   3.2.2.6.2. 收集器演进：CMS → G1 → ZGC（停顿与吞吐的权衡史）
   3.2.2.6.3. GC 调优与排查（OOM、内存泄漏定位）
   3.2.2.6.4. 手动管理回潮：Netty ByteBuf 内存池、堆外内存
   3.2.3. 通信效率（对抗网络的慢）
   3.2.3.1. 等待的艺术：五种 I/O 模型 → select/poll/epoll（C10K 问题，1999）
   3.2.3.2. Reactor 模式（单/主从多 Reactor）
   3.2.3.3. Java NIO：Channel、Buffer、Selector
   3.2.3.4. Netty：EventLoop 线程模型（→3.4.2.4 不共享范式）、Pipeline、编解码与粘包拆包
   3.2.3.5. 减少搬运：零拷贝（mmap/sendfile）、序列化效率、压缩、批量发送
   3.2.3.6. 演进叙事：Tomcat BIO → NIO → Netty → 虚拟线程（同一问题的三代答案）
   3.3. 应对策略 B：对抗不可靠 →【可用性技术】
   3.3.1. 可靠传输：TCP（握手挥手、确认重传、滑动窗口、拥塞控制、TIME_WAIT）
   3.3.2. 消息可靠性：MQ 的 ack、刷盘、消费语义（at-least-once/exactly-once）、消息顺序性
   3.3.3. 冗余：主从复制、集群、多活、两地三中心（→5.1 你的 Smart Invest 叙事）
   3.3.4. 自保：限流（令牌桶/漏桶）、降级、熔断、隔离舱、超时与重试（→3.4.1.4.6 重试必配幂等）
   3.3.5. 感知与切换：心跳、健康检查、故障转移、注册中心的成员管理职责
   3.4. 总派生：多拷贝协调 →【一致性技术】（终极战场）
   3.4.1. 四尺度同构（同一问题的四次投影，面试串讲主线）
   3.4.1.1. 硬件尺度：CPU 缓存一致性（MESI）、内存屏障、指令重排
   3.4.1.2. 单机线程尺度
   3.4.1.2.1. 线程安全的定义：原子性、可见性、有序性
   3.4.1.2.2. JMM：happens-before、volatile 语义
   3.4.1.2.3. 锁：synchronized 升级路径（偏向/轻量/重量）、CAS 与 ABA、AQS 体系（ReentrantLock/Semaphore/CountDownLatch）、死锁四条件与排查
   3.4.1.2.4. 并发容器：HashMap（线程不安全反例：扩容死循环/丢数据）、ConcurrentHashMap（分段锁→CAS+synchronized 演进）、CopyOnWriteArrayList、BlockingQueue 家族
   3.4.1.2.5. Iterator 体系：fail-fast vs fail-safe（一致性视图的两种承诺）
   3.4.1.2.6. ThreadLocal：原理、内存泄漏、与父子线程传递
   3.4.1.3. 单机进程尺度（数据库与缓存）
   3.4.1.3.1. 事务 ACID、隔离级别（一致性的可调刻度）
   3.4.1.3.2. MVCC（副本+协调范式的教科书实现）
   3.4.1.3.3. 锁机制：行锁、间隙锁、Next-Key Lock、死锁
   3.4.1.3.4. 缓存与库的一致性：Cache-Aside、延迟双删、订阅 binlog
   3.4.1.4. 集群尺度
   3.4.1.4.1. CAP 定理与 BASE（分布式的总宪法）
   3.4.1.4.2. 共识与复制：Paxos/Raft、quorum、主从复制延迟
   3.4.1.4.3. 分布式锁：Redis/RedLock、ZooKeeper、数据库实现及各自缺陷
   3.4.1.4.4. 分布式事务：2PC/3PC、TCC、Saga、本地消息表、事务消息、Seata
   3.4.1.4.5. 分布式缓存的一致性（→3.2.2.1 性能身份的另一面）
   3.4.1.4.6. 幂等性设计与对账补偿（最终一致的兜底）
   3.4.2. 四大解决范式（所有方案的母题，跨四个尺度通用）
   3.4.2.1. 互斥：synchronized、AQS、行锁、分布式锁
   3.4.2.2. 不可变：final、CopyOnWrite、快照读、函数式
   3.4.2.3. 副本+协调：MVCC、主从+共识、多版本
   3.4.2.4. 不共享：ThreadLocal、EventLoop 串行化、无状态服务、分库分表
4. 第二条根：认知约束——单个人脑的极限
   4.1. 总策略：抽象与分层（隔离变化、收敛认知）：架构分层、OSI、存储层级皆同源
   4.2. 解耦：IoC/DI 思想、面向接口、MQ 异步解耦、SPI 机制（JDK/Spring/Dubbo 三种实现）
   4.3. 复用与扩展：设计模式（按创建/结构/行为归类）、SOLID 原则、AOP 思想、模板方法
   4.4. 隔离与信任：类加载机制、双亲委派模型（信任链）、打破双亲委派的场景（SPI/热部署/容器隔离）
   4.5. 伪装（降低心智负担）：RPC 把远程伪装成本地、ORM 把表伪装成对象（及其泄漏的代价）
   4.6. 元编程基座（框架魔法的物理原理）：反射、动态代理（JDK/CGLIB）、字节码增强（ASM/Javassist/Instrumentation→Arthas）
   4.7. Spring 专题（认知约束应对的集大成者）
   4.7.1. IoC 容器与 Bean 生命周期（实例化→属性填充→初始化→销毁、三级缓存解决循环依赖）
   4.7.2. AOP 原理（→4.6 动态代理的应用）
   4.7.3. 声明式事务：@Transactional 传播行为与失效场景（→3.4.1.3 事务本体）
   4.7.4. SpringBoot 自动装配：@EnableAutoConfiguration、条件装配、spring.factories/imports（→4.2 SPI 思想）
5. 第三条根：经济与组织约束——规模与协作的极限
   5.1. 需求侧：互联网革命的经济学
   5.1.1. 信息复制/搬运边际成本趋零 → 用户规模爆炸 → 三高成为日常（→6）
   5.1.2. 全球状态互联 → 一致性升级到地球尺度（→3.4.1.4）
   5.2. 生产侧：软件的工业化
   5.2.1. 标准件体系：Java/JVM（一次编写到处运行）、强类型契约、向后兼容、Maven 生态
   5.2.2. 组织映射：康威定律 → 微服务拆分 = 用机器通信成本换人际协作成本（一切分布式麻烦的总根源）
   5.2.3. Spring Cloud 全家桶（按桶祛魅）
   5.2.3.1. 注册中心 Nacos/Eureka/ZK：成员感知（→3.3.5）+ 元数据一致性（→3.4.1.4.2，AP/CP 取舍）
   5.2.3.2. 配置中心：配置即需全局一致分发的状态（→3.4.1.4）
   5.2.3.3. 网关：统一入口 = 收敛认知（→4.1）+ 流量治理（→3.3.4）
   5.2.3.4. RPC/Feign：远程伪装本地（→4.5）、负载均衡
   5.2.3.5. Sentinel/Hystrix：自保三件套（→3.3.4）
   5.2.3.6. 链路追踪：TraceId 跨进程传播原理（→5.2.5）
   5.2.4. 交付流水线：CI/CD、容器（计算的标准集装箱）、K8s 编排
   5.2.5. 集体认知：可观测性三支柱（日志/Metrics/Tracing）——让组织"看见"系统
6. 汇合点：系统设计——三条根的工程总求解（面试压轴）
   6.1. 高性能 = 3.2 的组合拳：缓存、异步、池化、零拷贝、无锁化
   6.2. 高可用 = 3.3 的组合拳：冗余 + 自保 + 感知切换 + 容灾多活
   6.3. 高并发 = 3.2 × 3.4 的规模化：横向扩展 + 四大范式拆解竞争（热点打散、削峰填谷）
   6.4. 可扩展 = 数据与服务的再分布：分库分表、读写分离、冷热分离、单元化
   6.5. 权衡方法论：一致性 vs 性能/可用性、空间 vs 时间、通信成本 vs 协作成本——架构师的本职是定价与取舍
