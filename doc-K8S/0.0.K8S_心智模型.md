George，以你的背景（15 年 Java 后端、Spring Cloud、AWS EKS、Docker、微服务经验），学习 K8S 不应该从“命令大全”开始，而应该从**理解 Kubernetes 解决什么问题 → 核心对象 → 实战部署 → 生产架构**这条路线走。

K8S 本质上是：

> **一个管理大量 Docker 容器的分布式操作系统。**

你可以把它理解成：

```
                Kubernetes
        ┌────────────────────┐
        │  容器操作系统        │
        │                    │
        │  自动部署           │
        │  自动扩容           │
        │  自动恢复           │
        │  服务发现           │
        │  滚动升级           │
        └────────────────────┘
                 |
        -----------------
        |       |       |
      Docker  Docker  Docker
      容器    容器    容器
```

# 第一阶段：先建立 K8S 世界观（1天）

## 1. 没有 Kubernetes 的时代

假设你有一个 Spring Boot 服务：

```
用户
 |
 |
 Nginx
 |
 |
order-service.jar
 |
MySQL
```

后来业务增长：

```
             用户
              |
          Load Balancer
              |
       -----------------
       |       |       |
   order1   order2   order3
   Spring   Spring   Spring
```

问题来了：

### 问题1：机器挂了怎么办？

例如：

```
服务器A

order-service
    |
    X
  崩溃
```

人工：

```
发现故障
  |
登录服务器
  |
启动服务
  |
恢复
```

太慢。

---

### 问题2：流量突然增加怎么办？

平时：

```
2个实例

[order1]
[order2]
```

双11：

```
需要20个实例

[order1]
[order2]
...
[order20]
```

人工扩容痛苦。

---

Kubernetes 出现：

```
             Kubernetes

              发现故障
                 |
                 |
        自动重新创建容器


              崩溃
               |
               X

            自动恢复

             [new pod]
```

这就是 K8S 的核心价值：

> 你告诉 Kubernetes “我要什么状态”，它负责让现实达到这个状态。

# 你必须理解的 10 个核心对象

## 1. Cluster（集群）

整个 Kubernetes：

```
+--------------------------------+

          Kubernetes Cluster


     +-------------+
     | Master      |
     | 控制中心    |
     +-------------+


     +-------------+
     | Node        |
     | 工作机器    |
     +-------------+

     +-------------+
     | Node        |
     +-------------+

+--------------------------------+
```

---

## 2. Node（节点）

Node 就是一台服务器。

例如：

```
Node1

+----------------+
| Ubuntu         |
|                |
| Docker         |
|                |
| Pod             |
|  order-service |
+----------------+


Node2

+----------------+
| Ubuntu         |
|                |
| Docker         |
|                |
| Pod             |
| payment        |
+----------------+
```

类似：

AWS:

```
EC2 instance
      =
K8S Node
```

---

## 3. Pod（最重要）

很多初学者误解：

> Kubernetes 管理 Docker 容器？

不准确。

准确：

> Kubernetes 管理 Pod，Pod里面运行Container。

关系：

```
Kubernetes

     Pod

      |
      |
  ------------

  container
  container

```

为什么需要 Pod？

因为一个业务可能有多个紧密相关容器：

例如：

```
Pod

+--------------------+
|                    |
| Spring Boot        |
|                    |
| Sidecar            |
| 日志代理           |
|                    |
+--------------------+

```

---

但是90%的Java微服务：

```
一个Pod

     |
     |
Spring Boot Container
```

即可。

# 4. Deployment（部署）

这是 Java 工程师最容易理解的。

你现在：

```
java -jar app.jar
```

变成：

```
Deployment


我要：

3个order-service实例


       |
       |

 Kubernetes保证


 Pod
 Pod
 Pod

一直存在
```

字符：

```
Deployment

      |
      |
      v

 ReplicaSet


      |
 ----------------
 |       |       |
Pod     Pod     Pod

```

---

例如：

deployment.yaml

```yaml
replicas: 3

containers:
- name: order
  image: order-service:v1
```

意思：

```
我要3个order-service:v1

不要问我怎么启动

你自己保证
```

---

# 5. Service（服务发现）

这是微服务工程师必须掌握。

以前：

```
order-service

IP:

10.0.1.23

payment-service调用它


http://10.0.1.23
```

问题：

Pod 会变化：

今天：

```
Pod

10.0.1.23
```

明天：

```
Pod死亡

新的Pod

10.0.8.66

```

IP不稳定。

所以：

Service出现：

```
             Service

          order-service


              |
      ----------------

      |      |       |

    Pod    Pod     Pod


10.1.1  10.1.2 10.1.3

```

调用：

```
http://order-service
```

永远不变。

类似：

Spring Cloud Eureka:

```
服务注册中心
       |
       |
服务发现
```

K8S Service = 服务发现。

# 7. ConfigMap

配置文件：

以前：

```
application.yml
```

现在：

```
ConfigMap

    |
    |
Spring Boot

```

例如：

```
数据库地址

db.url=mysql.xxx.com
```

不写死在镜像里面。

 |

 |

 |
